# 13 — Motion & Micro-interactions

## Motion principle

_"You notice the quality of the interaction, but you don't notice the animation itself."_ — every motion spec below exists to communicate state change (something appeared, something is loading, something succeeded, hierarchy shifted), never as decoration. If a proposed animation doesn't map to one of those four purposes, it doesn't belong in the build.

## Rules

1. **Duration discipline**: use only the tokens in `02` (`100/180/240/400ms`). Never invent a one-off duration. Default is `duration-base` (240ms) unless a specific interaction below calls for another.
2. **No bounce, no elastic overshoot, no infinite decorative loops.** The single exception is the order-tracking current-stage pulse (`08`), which is a slow, subtle, purposeful "this is live" signal — and even that respects `prefers-reduced-motion` (`12`).
3. **Entrances decelerate, exits accelerate** — use `ease-decelerate` for anything appearing (toast, modal, sheet, scroll-reveal) and `ease-accelerate` for anything leaving.
4. **Layout-affecting animation must not cause content jump.** Skeletons match real content dimensions; accordion panels animate measured height, not a guessed fixed value; toasts and inline alerts reserve/animate their own space rather than shoving content abruptly.
5. **One motion idea per interaction.** Don't combine scale + rotate + color + shadow on a single button press — pick the one or two properties that best communicate the change (e.g. button press = scale only; card hover = image crossfade only).

## What is deliberately absent

Per brief ("do NOT use animation simply because animation is possible") — no page-transition wipes/slides between routes beyond standard browser navigation (unless implemented as an app-shell SPA, in which case route transitions use a simple `duration-fast` crossfade, nothing directional/cinematic), no parallax scrolling anywhere, no autoplay carousels that move without user input, no looping decorative animation outside the one named exception above, no hover states that trigger on scroll-into-view (hover is pointer-intent only).
